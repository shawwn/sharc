# Handoff: Compile-time global cells (2026-07-27)

## What was accomplished

Started from a `sb-sprof` profile of `(parse-hn-itemlist)` that looked like
an HTML-parsing profile but wasn't. Reading the totals column top-down,
one chain accounted for nearly everything:

```
  6   1  2.8   24 66.7   ARC::ARC-GLOBAL-REF
  7   1  2.8   14 38.9   SB-IMPL::GETHASH/LOCK
  8   1  2.8   13 36.1   (FLET "WITHOUT-INTERRUPTS-BODY-" :IN CALL-WITH-RECURSIVE-SYSTEM-LOCK)
  9   1  2.8   10 27.8   SB-IMPL::GETHASH/EQUAL
  3   4 11.1    5 13.9   STRING-DOWNCASE
```

Every free variable reference in Arc code was doing: allocate a
`string-downcase`d copy of the symbol name, `sxhash` it, take a mutex
(the table was `:synchronized t` at the time), and `equal`-compare
strings. The `__munmap` at 25% self and `nanov2_allocate_outlined` were
GC/allocator churn from the per-lookup key string. Roughly 90% of
sampled CPU was name resolution; `headmatch` showed 5 total / 1 self,
i.e. mostly a wrapper around global refs.

Fixed by resolving globals to **cells** at compile time. Committed as
**`0d6e994` "Resolve Arc globals to cells at compile time"** on
`untangle-features`.

## Files changed this session

Both in commit `0d6e994` (91 insertions, 9 deletions):

- **`arc0.lisp`**, globals section rewritten:
  - `*arc-unbound*` -- a `defvar`'d uninterned symbol used as the
    "unbound" marker in a cell's value slot. `defvar` (not `defparameter`
    /`defconstant`) so its identity survives reloading the file.
  - `gcell` defstruct: `name` (read-only) + `value`. Has a
    `:print-object` that prints `#<gcell foo>` and **deliberately omits
    the value** -- cells appear inside compiled code, which is printed in
    backtraces, and a global's value can be huge or circular.
  - `*arc-globals*` now maps lowercase name string -> gcell (it is the
    interning map, no longer on the hot path). `*arc-globals-lock*`
    serializes cell creation only.
  - `find-gcell` (lookup, nil if absent) vs `intern-gcell`
    (create-if-absent, double-checked under the lock).
  - `gcell-ref` (strict read, errors when unbound) and `gcell-unbound`
    (the out-of-line error).
  - `arc-global`, `(setf arc-global)`, `arc-bound-p`, `arc-global-ref`
    reimplemented on top of cells with **identical external semantics**.
- **`arc1.lisp`**:
  - `ac-var-ref`: `(gcell-ref ,(intern-gcell s))` instead of
    `(arc-global-ref ',s)`.
  - `ac-set1`: `(setf (gcell-value ,(intern-gcell a)) zz)` instead of
    `(setf (arc-global ',a) zz)`.
  - `ac-macro-p`: uses `(arc-global fn)` instead of reaching into the
    table with `gethash` directly.

After this commit, `*arc-globals*` is touched only inside `arc0.lisp`.

## Key decisions

- **Cells, not CL symbol value cells.** Using `symbol-value` on interned
  `arc--NAME` symbols would have been marginally faster (native unbound
  marker, no explicit check), but Arc globals interact with the
  thread-local/`the` machinery and dynamic binding, and hijacking CL
  special variables for them risked subtle collisions. An explicit box
  keeps the semantics under our control.

- **`gcell-ref` is NOT declaimed inline. This is the important one.**
  The first version inlined it, which looked great on micro-benchmarks
  and then made `./test.arc` go from 1.40s to 2.39s. Arc compiles a
  fresh CL form for every top-level expression and every `fn` body, and
  `gcell-ref` lands at *every free variable reference* -- thousands of
  sites -- so inlining it inflated IR1 and emitted code for everything
  Arc compiles. Profiling `(load "test.arc")` showed the run dominated
  by `alloc_code_object`, `SB-C::*`, and the assembler.

  Moving just the `error` out of line (`gcell-unbound`) recovered only
  2.39s -> 2.13s. Removing the `inline` declaim entirely gave 1.35s.
  A comment above `gcell-ref` records this; **do not "optimize" it back
  to inline without re-timing `./test.arc`.**

  Note the *assignment* path stays fully inline (defstruct accessors
  always are): `(setf (gcell-value cell) zz)` is a bare slot write with
  no error branch, so it costs nothing to compile.

- **Split `find-gcell` / `intern-gcell`.** The compiler must intern even
  for still-unbound names (forward references and recursive definitions
  are compiled before the name exists), but runtime probes must not
  create entries, or `(bound 'x)` would start returning `t` for a name
  that was merely *referenced*. `arc-global`/`arc-bound-p` use
  `find-gcell`; `ac-var-ref`/`ac-set1`/`(setf arc-global)` use
  `intern-gcell`.

- **Explicit unbound marker instead of `gethash`'s second value.** A
  global legitimately bound to `nil` must not error, which is why the
  old code used `multiple-value-bind ... present`. Cells need the same
  distinction, hence `*arc-unbound*`.

- **Interning takes a lock; the hot path does not.** `:synchronized t`
  was dropped from `*arc-globals*` (that removal was already staged
  locally and is subsumed by `0d6e994`). Reads and writes of a *bound*
  global are now a plain slot access; only creating a cell for a
  not-yet-seen name is serialized, which happens at compile/definition
  time, not per reference.

- **No `make-load-form` for `gcell`.** Arc-compiled forms are only ever
  `eval`'d in-memory, never `compile-file`'d, and structures are
  self-evaluating (CLHS 3.1.2.1.3), so embedding the cell as a literal
  is safe. See "Things to watch" if that ever changes.

## Measured

Baseline was the pre-change `arc0.lisp`/`arc1.lisp` extracted with
`git show :arc0.lisp` into a `git worktree`, driven against the *same*
`.arc` files via `ARC_DIR=/Users/shawn/ml/sharc22-experiment/
<worktree>/sharc <abs path>`. That trick is worth reusing: it isolates
runtime changes from working-tree `.arc` edits, and sidesteps the
worktree lacking the untracked `arc/` data dir.

Micro-benchmarks (300k-1M iterations each, three runs, all within ~3%):

| | before | after |
|---|---|---|
| empty loop | 84 ms | 34.7 ms |
| global read | 113 ms | 38.4 ms |
| global fn call | 112 ms | 42.9 ms |
| 3-arg fn call | 159 ms | 61.2 ms |
| global assign | 129 ms | 34.2 ms |
| `headmatch` x200k | 271 ms | 109 ms |
| `posmatch` over 20KB | 22 ms | 8.9 ms |
| `tokens` x20k | 2,400 ms | 537 ms |

`./test.arc` wall time: 1.40s before, 1.35s after (it is compile-bound,
so it shows almost none of the runtime win; it is however the canary
that caught the inlining regression).

Re-profiling a CPU-bound workload afterwards, the entire old chain is
gone: no `ARC-GLOBAL-REF`, no `GETHASH/*`, no `STRING-DOWNCASE`, no
`SIMD-CMP-8-32`. Top entries are now `ARC-IS2`, `ARC-CALL2`,
`ARC-COERCE`, `reduce`, `rev`.

## Verification

- `./sharc test.arc` -> **779 passed, 0 failed**
- A semantics script exercising what the indirection could plausibly
  break, all passing: `bound` of a never-mentioned name; `bound` of a
  name that was *referenced* but never assigned; `(= x nil)` still reads
  as bound; unbound read errors with the same `Unbound variable: NAME`
  message; forward references; a closure compiled against a cell seeing
  a later redefinition; assignment through a compiled cell visible to
  `eval`; case folding of mixed-case global names.
- News server (`(load "news.arc")` then `(nsv)`): boots, binds 8080,
  returns HTTP 200.
- Cells render compactly in real backtraces:
  `(ARC::GCELL-REF #<gcell load>)`.

## Things to watch

- **Do not declaim `gcell-ref` inline.** See above. Re-time
  `./test.arc` (not just a runtime micro-benchmark) after any change to
  what `ac-var-ref` emits -- the two pull in opposite directions.

- **If Arc-compiled forms are ever dumped to a fasl**, `gcell` will need
  a `make-load-form` that re-interns by name, e.g. returning
  `` `(intern-gcell ,(gcell-name c)) ``, or identity across the dump
  will be lost and compiled code will reference dead cells. Nothing
  does this today.

- **Reloading `arc0.lisp` in a live image** redefines the `gcell`
  defstruct and invalidates existing instances. Reloading `.arc` files
  is fine (cells are mutated in place); reloading the CL runtime needs a
  restart. This was already true of `arc-tagged`.

- **Unbound-variable messages now come from `gcell-name`** (the
  lowercase key string) rather than the symbol. Output is identical in
  practice, since `~A` on an Arc symbol princs its already-lowercase
  name, but exact-string assertions on that message should be aware.

- **Pre-existing news failure, not caused by this work.** Serving
  `/news` from the current working tree returns HTTP 200 with a 0-byte
  body and logs `Error: Assertion failed: (uid->user* i!by)` in `by`.
  The pre-change build does exactly the same, so it is in the
  uncommitted `news.arc` WIP or the local `arc/` data (`load-news` only
  calls `load-users` when `initload-users*` is set, so `uid->user*` can
  be empty). Do not chase it as a regression from the cell change.

## `atomic-invoke` (tried, benchmarked, reverted)

Separately, `atomic-invoke` was briefly rewritten from the hand-rolled
reentrant mutex (`*arc-atomic-owner*` + `with-mutex`) to
`sb-thread:with-recursive-lock`, then reverted after benchmarking. It is
back to the hand-rolled version as of this handoff. Numbers at 300k
iterations, recorded so the experiment does not need repeating:

| | old (`*arc-atomic-owner*`) | `with-recursive-lock` | `holding-mutex-p` |
|---|---|---|---|
| `(atomic (noop))` | 19.4 ms | 19.4 ms | 19.5 ms |
| nested x2 | 21.2 ms | 26.8 ms | 21.8 ms |
| nested x3 | 23.1 ms | 33.5 ms | 23.7 ms |

Outermost acquisition is unchanged (both reach the same
`call-with-mutex`). The *reentrant* path costs ~6ns before and ~23ns
after: `sb-thread:call-with-recursive-lock` is a 976-byte out-of-line
function that type-checks the mutex, reads `mutex-%owner`, checks
`*INTERRUPTS-ENABLED*`, and sets up a full unwind-protect block even
when the thread already owns the lock. With 42 `atomic`/`atlet`/`atwith`
sites in the tree this is microseconds per request, i.e. irrelevant in
practice.

If both the simplification and the old speed are wanted:

```lisp
(xdef atomic-invoke (f)
  (if (sb-thread:holding-mutex-p *arc-mutex*)
      (arc-call0 f)
      (sb-thread:with-mutex (*arc-mutex*)
        (arc-call0 f))))
```

That drops the separate owner special variable (so it cannot desync)
while keeping the reentrant path inline; measured back at the old
numbers, 779 tests pass.
