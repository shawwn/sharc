## hn.js is now the client JS

`static/hn.js` (HN's verbatim client js) replaces the old inline
`votejs*`, loaded as an external, content-hashed script:
`(tag (script src (static-src "hn.js")))`. It installs a **global click
handler** on `document` that intercepts any `<a class="clicky">`, reads
its href, and dispatches by path: `/vote` -> `vote()`, `/hide` ->
`hidestory()`, a `.togg` element -> `toggleCollapse()`, otherwise scrolls
to the URL hash. So enabling a feature = emitting the right `clicky`
markup + wiring the server op.

`votejs*` is now unused (left in place; can be removed).

## Voting (done, `d8fa051`)

The whole vote/unvote cycle works against hn.js:

- **vote links** (`votelink`): `<a id="up_<id>" class="clicky"
  href="vote?id=<id>&how=up&auth=<cookie>&goto=<whence>">`. Dropped the
  old `onclick="return vote(this)"`. `vote-url` emits HN's param names
  (`id`/`how`/`auth`/`goto`) that hn.js reads.
- **vote op**: `(newsop vote (id how auth goto) ...)`. Gets the user from
  the session (cookie), verifies `auth == (user->cookie* user)` (CSRF),
  handles `up`/`down`/`un`. Logged-out (non-clicky) clicks still navigate
  to the login page.
- **unvote-for**: the inverse of `vote-for` (reverses score and karma,
  removes the vote from `i!votes`, `(votes* (me))`, `(uvar (me) votes)`),
  for the `how=un` link hn.js injects.
- **nosee arrows**: the key trick. After voting, the arrows stay in the
  DOM but get `class="clicky nosee"` (news.css `.nosee` =
  `visibility:hidden; pointer-events:none`), so hn.js's
  `vis($('up_'+id), how=='un')` can un-hide them on unvote. So:
  - `votelinks` renders arrows whenever the item is votable *in principle*
    (logged-out -> click goes to login; logged-in -> real vote), not only
    when un-voted. Author still shows `*`.
  - `canvote` gained `(o ignore-voted)` so `votelinks` can ask "could you
    vote here, voted-status aside?" (passes `t`); the op keeps the strict
    check (default nil).
  - `votelink` adds `nosee` when `((votes) i!id)`.
- **persistent unvote link**: `byline` renders the unvote/undown link
  server-side in the `<span id="unv_<id>">` when the user has voted
  *someone else's* item (`(~author i)` -- you auto-upvote your own and
  can't unvote those), so it survives a refresh and matches hn.js's
  injected markup exactly. `whence` was threaded through
  `itemline`/`byline` for the link's `goto`.
- removed the `<br>` between the up/down arrows (the `votearrow` divs are
  block-level and stack on their own; the `<br>` was a leftover from the
  inline-`<img>` era and added a blank line).
- `downvote-threshold*` 200 -> 0 (so testing accounts can downvote).

### Full cycle
not voted: arrows visible (`clicky`), no unvote link -> click up: hn.js
adds `nosee` (hides arrows), injects unvote link, pings vote; server
records -> refresh: server renders the same (nosee arrows + unvote link)
-> click unvote: hn.js removes `nosee` (arrows reappear), pings `how=un`;
`unvote-for` reverses it -> refresh: back to start.
