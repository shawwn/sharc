# Handoff: HTTP client with native SSL (2026-05-26)

Added a full HTTP client to the Arc runtime (`arc0.lisp`) that talks
HTTPS natively via OpenSSL's FFI, with no external CL dependencies.

## Arc API

### socket-connect

```arc
(socket-connect host port [opts])
```

Opens a TCP connection, returns a bidirectional stream that works with
`readc`, `writec`, `disp`, `write`, `close`, `flushout`. SSL is
auto-enabled for port 443.

opts (table):
- `ssl` -- force SSL on any port
- `noverify` -- skip certificate verification

### http-fetch

```arc
(http-fetch url [opts])
```

HTTP request; returns the response body as a string. Errors on
non-2xx status.

opts (table):
- `method` -- HTTP method string (default "GET")
- `headers` -- alist of `("Header-Name" "value")` pairs
- `body` -- request body string
- `noverify` -- skip certificate verification

All five standard methods tested: GET, POST, PUT, DELETE, PATCH.

### flushout

Updated to accept an optional stream argument (defaults to stdout).

```arc
(flushout)     ; flush stdout
(flushout s)   ; flush any stream
```

## Implementation details

### SSL loading

OpenSSL is loaded at startup via `sb-alien:load-shared-object`. On
macOS, only explicit Homebrew paths are tried (`/opt/homebrew/lib/`,
`/usr/local/lib/`) to avoid Apple's restricted system libcrypto which
causes a fatal SIGABRT. On Linux, bare library names are tried
(`libssl.so`, etc.). On Windows, the dll names are listed but untested.

If loading fails, `*ssl-available*` is nil; startup is unaffected and
only HTTPS requests error at runtime.

### Certificate verification

Enabled by default via `SSL_CTX_set_default_verify_paths` (system CA
store) + `SSL_CTX_set_verify` with `SSL_VERIFY_PEER` +
`SSL_set1_host` for hostname matching. CTX verify settings are applied
before `SSL_new` so they propagate correctly.

On failure, the error message includes the specific X509 reason from
`SSL_get_verify_result` + `X509_verify_cert_error_string`:
- `certificate has expired`
- `hostname mismatch`
- `self-signed certificate`

The `noverify` option skips all of this for dev/internal use.

### Gray streams for SSL

`arc-ssl-stream` is a bidirectional gray stream wrapping SSL_read /
SSL_write. It buffers reads (SSL_read returns bytes, decoded to chars)
and writes (chars accumulated, flushed as bytes). This lets all
existing Arc I/O primitives work transparently over SSL connections.

### Headers

User headers in `http-fetch` are alist-only (not tables) so order is
preserved and string keys work naturally.

## Key decisions

- No Quicklisp: cl+ssl would have required vendoring ~10 transitive
  deps. Direct sb-alien FFI to libssl is ~20 function bindings.
- `http-fetch` not `http-get`: supports all HTTP methods via the
  `method` option.
- Tables can't store nil values in Arc (setting a key to nil deletes
  it), so the cert escape hatch is `noverify` (truthy) rather than
  `verify nil`.
- Headers are alist-only after discussion; table keys are symbols
  which is awkward for HTTP header names that are conventionally
  strings.
